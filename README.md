# Swarm Pepe: your slot is live

**Video:** [artifacts/video.mp4](artifacts/video.mp4)

A 25-second message for wallets in the newly granted mint batch. It announces the slot, explains that slots are earned through work for the swarm, then shows both claim paths: call `claim()` with no arguments through a block explorer, or send 0 ETH to the Swarm Pepe contract. The last section explains why the art appears later. The final frame includes `generated by $IMD swarm`.

## Delivery

| Item | Value |
| --- | --- |
| Duration | 25.000 seconds |
| Canvas | 960 × 540 pixels, 30 fps |
| Video | H.264, yuv420p, MP4 with front `moov` atom |
| Audio | AAC, mono, 22.05 kHz; original synthesized chip score |
| Output | `artifacts/video.mp4` |

The visual language follows the [earlier Swarm Pepe film](https://github.com/identity-md-launches/launch-449-make-25-second-video-swarm): blue cast near-black grid, cream monospace bitmap type, lime and orange accents, thin HUD frame and bottom metadata strip. Cuts are hard; there are no fades. No wallet address, ENS name, or personal data appears on screen.

## Token provenance

**Minted token IDs shown:** 13, 21, 34, 55, 89, 144, 233, 377.

At Ethereum mainnet block **26,084,721** (`0x18e0571`), [source/fetch_tokens.py](source/fetch_tokens.py) called `SwarmPepe.ownerOf(id)` to confirm minting, then `SwarmPepe.seedOf(id)` and `PixelArt.renderSVG(seed)` for every portrait. The exact returned SVGs are under [assets](assets), and [assets/provenance.json](assets/provenance.json) records each seed and SVG SHA-256 hash.

- [SwarmPepe contract](https://etherscan.io/address/0x999ce0ce8c5f7661e0c74a568ffe27ceb9177bdb)
- [PixelArt contract](https://etherscan.io/address/0x07Fd9841eEB6a359EfB30f861D59bFa1f6B03FcA)

[source/build_video.py](source/build_video.py) rasterizes each SVG to its native 24×24 grid, then enlarges it only by integer pixel replication. The surrounding typography and interface graphics are separate from the on-chain portraits.

## Rebuild and checks

With Python 3 and FFmpeg installed, run `python3 source/build_video.py`. It rebuilds the MP4 offline from the included SVGs. `python3 source/fetch_tokens.py 13 21 34 55 89 144 233 377` refreshes the art from Ethereum when network access is available.

The delivered file was checked with `ffprobe`: H.264 video, AAC audio, 960×540, 30 fps, and 25.000-second container duration. FFmpeg measured non-silent audio (mean −19.2 dB, peak −3.0 dB). Frames from every section and the last frame were inspected; the `moov` atom precedes `mdat`.

**Limitations:** The `978 / 5000` figure is a fixed brief-time snapshot and can change. The clip addresses granted wallets but does not check an individual wallet's eligibility. H.264 yuv420p compression can cause minor color bleed at pixel edges even though artwork scaling is nearest-neighbour only.
